GC-DOC-03: bloqueo cooperativo de escritor mediante creación exclusiva de sidecar .goosecad-lock, descriptor abierto y comprobación de identidad antes de retirarlo; no se roba bloqueo preexistente. Token SHA-256 de bytes exactos mediante load_with_revision y save(expected_revision=token); None exige ausencia, omitir conserva API incondicional anterior. Conflicto se detecta antes de modificar principal o .previous. El bloqueo cubre validación, copia anterior, reemplazo y fsync. 115 pruebas locales aprobadas (12 nuevas), incluidas dos escrituras desde procesos independientes y terminación abrupta simulada, conflicto obsoleto, desaparición, modificación externa, migración v1/v2 y sidecar ajeno. 400 muestras nuevas (7760 acumuladas). Medianas finales: sin lock (bypass experimental aislado) 1.935070 ms, con lock 2.030293 ms, con lock+token 2.010160 ms; lock aislado 0.067229 ms. No se atribuye beneficio a diferencias entre rondas. El coste de protección es pequeño en este entorno.
Limitaciones: escritor cooperativo en ruta/directorio local confiable, no protege de programas ajenos al protocolo, alias extraños, directorios hostiles ni sistemas de archivos de red; comprobar durabilidad real y Windows. Un proceso muerto deja sidecar y exige recuperación manual después de confirmar que no hay escritor activo; no se borra automáticamente. Si falla fsync de directorio o limpieza del lock tras replace, el guardado podría haber ocurrido; releer antes de reintentar. Token compara bytes, no detecta cambios que vuelvan a exactamente los mismos bytes. El modo legado sin expected_revision no protege de revisión obsoleta; la futura UI debe usar tokens siempre. No hay sandbox ni autenticación, undo/redo persistente, curvas/agujeros o UI. OCAF aislado, Goose/C++ OCCT real bloqueado. Próximo GC-SKETCH-03: perfiles curvos exactos y agujeros.
